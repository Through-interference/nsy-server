# Контракт bvs-camera ↔ nsy-server, версия 1

Приложения запускаются независимо и не импортируют пакеты друг друга.
Небольшие описания метрик и IP-carrier продублированы в обоих репозиториях;
при их изменении нужна совместимая версия на двух концах.

## Видео и WFB

| Данные | Значение |
|---|---|
| Видео до WFB | RTP/UDP; H.264 PT96 или JPEG PT26, clock-rate 90000 |
| Видеопорт на Pi | 127.0.0.1:5600 |
| Прямой поток WFB | stream 0, общий link_id |
| Обратный поток WFB | stream 1, тот же link_id и парные ключи |
| Обратные метрики на Pi | UDP 127.0.0.1:5801 → HTTP POST 127.0.0.1:8090/feedback |
| Управление бортовым WFB TX | UDP 9001, только локальное управление |
| HTTP контроллера | 127.0.0.1:8090 |

HTTP API не публикуется на интерфейсе Wi-Fi. Для удалённого управления
используется SSH-туннель.

## Метрики

JSON содержит обязательные `rssi`, `snr`, `pre_loss`, `post_loss`, `active`.
RSSI/SNR могут быть null, потери — доли 0..1, active — boolean. `source` принимает
wfb, wfb-ip или simulation; последний допустим только в диагностическом режиме.
Дополнительные поля: receiver_overloaded, decoder_fps, input_fps, rx_queue_ms,
receiver_cpu_percent, receiver_temp_c. Неизвестные типы/нечисловые значения
не должны превращаться в нормальную статистику.

В wfb-ip RSSI/SNR равны null: debug-заголовок не измеряет радиосигнал.
Контроллер работает с потерями/нагрузкой, а физический MCS управляется ОС/AP.

## IP-carrier

Борт слушает UDP 17030 на указанном IPv4; НСУ открывает сессию первой.
Внешняя обёртка: ASCII `SKZ1`, затем байт H (hello), A (ack), D (данные).
H/A без тела, D переносит непустой WFB debug-forward datagram до 8192 байт.
Борт принимает peer только с настроенного IP, lease — 5 секунд; keepalive НСУ
каждые 0,5 секунды. Внутри остаются настоящие шифрованные/FEC-пакеты WFB.
Внешний peer-фильтр — не дополнительная криптографическая аутентификация.

Этот транспорт не эквивалентен прямым 802.11 monitor/injection кадрам.
